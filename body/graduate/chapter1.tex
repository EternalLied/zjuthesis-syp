\section{研究背景及意义}
% \subsection{分布式训练的发展}

过去十余年中，深度学习在计算机视觉、自然语言处理与科学计算等方向持续取得突破，
其核心推动力来自于模型结构的创新与算力基础设施的快速建设
\cite{fukushima1980neocognitron,he2016deep,vaswani2017attention}。
一方面，随着大语言模型（Large Language Model，LLM）的迅速发展，训练数据集规模从经典视觉数据集（如 ImageNet）的上百 GB 量级\cite{deng2009imagenet}扩展到近 TB 量级（如 The Pile 达到 825\,GB\cite{gao2020pile}，ROOTS 超过 1.6\,TB\cite{workshop2022bloom}）；
另一方面，大规模神经网络模型的训练过程涉及大量矩阵运算，
使得训练所需的计算量与系统资源需求持续增长
\cite{fedus2022switch,zhang2022opt,brown2020language}。
近年来代表性深度学习模型在训练阶段所消耗的计算量变化趋势
如\autoref{fig:Fig1-1} 所示（数据来源：Epoch AI），可以观察到模型训练所需的计算规模
在时间维度上呈现出显著的增长态势。

随着数据规模、模型参数量和任务复杂度的不断提升，单个计算节点（一般为GPU）的计算与存储能力逐渐无法满足训练要求，模型训练逐步由单节点训练转向依赖多节点集群协同的分布式训练。
分布式训练中，要进行节点间的任务划分，通过特定的并行训练方式实现高效协同。
常用的并行训练方式有数据并行（Data Parallelism，DP）和模型并行，模型并行包括张量并行（Tensor Parallelism，TP）、流水并行（Pipeline Parallelism，PP）和专家并行（Expert Parallelism，EP）等\cite{王恩东2024分布式训练系统及其优化算法综述}。
数据并行中，每个节点持有整个模型的副本，并在划分的本地数据集上进行训练，完成一次迭代后对各本地梯度进行聚合，然后更新参数，以保持不同节点模型间的同步。然而，数据并行可能无法满足大规模模型的训练需求，这些模型可能超出设备的存储和计算能力，因此，模型并行的使用变得不可避免。
% 模型并行包括张量并行、流水并行和专家并行等方式。
张量并行是一种应用广泛的模型并行方法，通过将模型参数张量进行切分，使不同分块在不同节点上并行计算，并依靠计算过程中的必要同步操作保证切分前后的数学等效性。该方法能够有效减少单个节点的显存占用，但节点间需要频繁进行参数同步通信。
流水并行将神经网络模型按层切分为多个阶段，并将各阶段分配到不同节点上，各节点分别负责对应阶段的计算，并在前向与反向传播过程中通过点对点通信传递激活值与梯度。
% 流水并行存在着Bubble现象，即在某些时间段内，部分节点处于空闲状态，无法充分利用计算资源。为了解决这一问题，可以采用微批次（Micro-batch）技术，将输入数据划分为更小的批次，并在流水线中交错处理这些微批次，从而提高资源利用率和整体训练效率。
专家并行是一种面向混合专家模型（Mixture of Experts，MoE）设计的并行策略，将模型中的不同专家模块分配到不同计算节点上，实现高效的模型训练与推理。
各种并行训练模式示意图如\autoref{fig:parallel_pattern}所示，图中不同颜色的方块代表模型的不同层或组件，箭头表示数据流动方向，虚线表示模型的划分边界。

无论采用何种并行训练方式，分布式训练任务都需要进行计算节点间的相互通信，以保证全局模型参数和梯度等数据的一致性。这些通信操作通常通过集合通信（Collective Communication）来实现，包括 AllReduce、AllGather、ReduceScatter 和 AlltoAll 等算子。每种算子定义了全局各节点需要发送和接收的数据及其组织方式，其中 AllReduce 是最常用的算子，被广泛用于数据并行中的梯度同步与张量并行中的参数同步。

随着模型规模与训练数据的不断增长，分布式训练中的通信开销日益凸显，逐渐成为制约训练效率与系统可扩展性的关键因素。\autoref{fig:llm_bw} 给出了在 FP8 量化条件下，稠密大模型训练对显存带宽的理论需求随模型规模增长的变化趋势（数据来源：SemiAnalysis）。可以观察到，随着模型参数规模从百亿级扩展至万亿级，理论带宽需求呈现快速增长，并逐渐逼近甚至超过当前主流 GPU 加速器及其集群所能提供的实际带宽上限。分布式训练的理想状态是获得接近线性的加速比，即训练时间随计算节点数量的增加而近似按比例缩短。然而在实际系统中，加速比往往呈现先提升后下降的趋势：当节点规模较小时，新增算力能够有效提升训练吞吐；而当规模进一步扩大，通信与同步开销迅速累积，计算设备需要等待全局同步而处于长时间的空闲状态，导致整体资源利用率下降\cite{朱泓睿2021分布式深度学习训练网络综述,王帅2022}。这表明通信与数据搬运已成为大模型分布式训练的主要性能瓶颈，其效率在很大程度上决定了分布式训练在大规模场景下的可行性与扩展性。

为了缓解大规模分布式训练中的通信瓶颈，在算法层面可以从两方面进行优化：一方面，通过优化集合通信算法本身来提升通信效率、降低通信开销。该方向包含两种主要思路：一是人为设计具有固定算法逻辑的高效集合通信算法，本文将其概括为\textbf{集合通信算法设计}；二是针对复杂的物理网络拓扑，通过问题建模与优化求解的方式，在不同网络环境下自动合成高效的集合通信算法，本文将其概括为\textbf{集合通信算法自动合成}。另一方面，通过改进训练流程中计算与通信算子的调度策略，实现计算与通信的并行执行，将部分通信开销从关键路径中隐藏，从而减少通信对端到端训练时间的影响，本文将其概括为\textbf{计算通信并行优化}。

基于此，本文围绕分布式训练中的集合通信算法优化与计算通信并行优化问题展开研究，旨在提升集合通信的效率与计算通信并行度，从而加速大规模分布式训练任务的执行。

% 模型训练中的通信是每次训练迭代的常态开销，在不同并行策略下呈现出不同的特征与需求。在数据并行中，梯度同步通常通过 AllReduce 完成；在张量并行中，为保证切分张量的语义一致性，计算操作需要与 ReduceScatter、AllGather 或 AllReduce 等通信操作按数据依赖关系配合执行；在流水并行中，相邻流水阶段的设备需要频繁进行点对点通信以传递激活值与梯度；在 MoE 专家并行中，大规模特征重分发使得 AlltoAll 被频繁调用。随着训练模式从单一并行演进为多维度混合并行，集合通信的种类与调用频率显著增加，其在端到端训练时间中的占比持续上升。

% 与此同时，实际集群的硬件结构也在持续演化，呈现出层次化与异构化特征：机内可能同时存在 NVLink、PCIe 等不同带宽的链路，机间通过 RoCE、InfiniBand 等网络互连，多级交换机引入端口并发与转发模式等约束。传统固定通信模板（如单一 Ring 或 Tree）在复杂拓扑下往往难以同时兼顾低时延与高带宽利用率，且对多链路并行能力挖掘不足，导致通信效率不足、训练时长延长以及昂贵算力资源的闲置与能耗浪费。

% 基于上述分析，围绕分布式训练中的通信进行优化具有重要意义。本文从三个层面展开研究：（1）针对环形集合通信算法，通过改进通信流程减少通信轮数、提升链路利用率，在常见硬件环境中直接提升通信效率；（2）针对复杂拓扑结构，通过集合通信算法自动合成技术，在交换机网络与异构网络环境下自动构造高质量的数据路由与链路并发方案；（3）针对张量并行等场景，通过计算与通信的细粒度并行化调度，将部分通信开销从关键路径中隐藏，进一步提升端到端吞吐。



\section{国内外研究现状}

% 围绕分布式训练中的通信瓶颈，学术界与工业界已经形成了较为系统的研究体系。从问题形态上看，相关工作大致可以归纳为三类：（1）集合通信算法设计，聚焦于为具体集合通信算子构造更高效的通信流程；（2）集合通信算法合成，强调在给定物理拓扑与资源约束下自动合成调度；（3）计算通信并行优化，通过调度与算子拆分将通信开销从关键路径中尽可能隐藏。下面将按上述脉络对国内外研究进展进行梳理。



\subsection{集合通信算法设计}
                                                                          
集合通信算法设计是指通过人工构造具有固定逻辑结构的通信流程，为 AllReduce、AllGather、ReduceScatter 和 AlltoAll 等基础算子提供高效实现。这类方法的核心在于如何组织节点间的数据传输顺序与并行方式，以在满足算子语义的前提下降低通信时延、提升带宽利用率。围绕上述算子的高效实现，学术界与工业界提出了多种经典算法。根据算法结构特点，现有工作主要包括环形拓扑算法及其改进、多维与树形扩展算法、分层与分组算法等类型。下面将按此脉络对相关研究进展进行梳理。

Ring AllReduce 是一种十分经典且目前仍广泛应用的集合通信算法。该算法在高性能计算领域被证明具有带宽最优性质\cite{patarasuk2009bandwidth}，并被成功引入深度学习训练实践\cite{gibiansky2017hpc}。具体地，Ring AllReduce 将节点组织成环形逻辑拓扑，其整体流程可视为前 $(n-1)$ 轮 ReduceScatter 与后 $(n-1)$ 轮 AllGather 的串联：通过对数据进行均匀切分并逐轮转发，最终每个节点获得完整的归约结果。该算法的优势在于通信负载均衡、实现简单且易于部署；其不足之处在于通信轮数随节点数量线性增长，在多链路并存或链路性能不均衡的环境下，整体性能容易受制于最慢链路。
随后，围绕环形结构通信轮数偏多的问题，研究者提出了改进算法。De 等人提出的 Swing 算法\cite{de2024swing}在保持 Ring 算法整体结构不变的前提下，通过在逻辑环中引入捷径通信路径，减少数据在环上的传播距离，从而提升有效带宽。Hammer 等人进一步提出了 Short-circuiting Ring 方法\cite{hammer2025short}，通过在环形通信过程中引入跨节点的短路转发机制，降低通信路径上的累积时延，在保持 Ring 算法简单性的同时改善其在大规模系统中的时延性能。

针对 Ring 算法通信并行度受限、难以充分利用多维网络拓扑的问题，研究者提出了多维与树形扩展算法。索尼针对大规模图像分类训练中的通信瓶颈，提出 2D-Torus 方法\cite{mikami2018massively}，将设备组织为二维网格结构，通过在不同维度上依次执行 ReduceScatter、Ring AllReduce 和 AllGather 操作，使多条链路并行传输数据，有效提升了通信并行度。谷歌在此基础上，针对 TPU 等专用互连硬件的特点对该流程进行了简化与优化\cite{ying2018image}。然而，上述多维算法在节点数量较多时仍面临通信轮数较多的问题。为降低通信轮数，树形算法被引入集合通信领域。Thakur 等人提出递归二分与倍增（Recursive Halving and Doubling，HD）AllReduce\cite{thakur2005optimization}，可在 $\log_2 n$ 轮内完成归约与分发，在消息规模较小的场景下显著降低启动时延。但该算法每轮通信的对端节点均会变化，在实际部署中需要频繁重建连接，限制了其在高频通信场景下的适用性。针对该不足，阿里巴巴在自建 EFLOPS 集群中对该算法进行了工程优化\cite{dong2020eflops}。NVIDIA 进一步提出双二叉树（Double Binary Tree）结构\cite{sanders2009two}，通过固定通信连接并采用双树并行传输，在保持对数级通信轮数的同时实现了算法带宽最优性，在跨机场景下的机间 AllReduce 中表现出较强的性能优势。

随着集群规模的不断扩大以及网络层级结构的日益复杂，单一通信结构难以同时兼顾不同层级链路的性能特性。为此，研究者提出了一系列基于分组与分层思想的算法设计方法。这类方法通常在高带宽域内执行更密集的通信操作，在低带宽域内减少通信负载，以缓解跨层通信瓶颈。腾讯提出的分层 Ring AllReduce\cite{jia2018highly}通过“组内—组间—组内”的通信流程，有效兼顾了机内高速互连与机间网络的性能差异。IBM 的 BlueConnect\cite{cho2019blueconnect}将 AllReduce 拆分为多阶段 ReduceScatter 与 AllGather 操作，并通过整数分解构造多维分组，以增强算法在多层网络结构下的适应能力。围绕分层通信的进一步优化，还包括通过流水线并行方式掩盖部分通信开销的相关工作\cite{thao2021efficient}。

除 AllReduce 相关研究外，多对多通信算子 AlltoAll 也是分布式训练中的重要基础算子，尤其在混合专家（MoE）等模型结构中被频繁调用。针对 AlltoAll 的高效实现，研究者提出了多种基于显式算法结构的设计方法。早期工作中，Bruck 等人提出了基于循环移位的数据交换算法\cite{bruck1994efficient}，能够以对数级通信轮数完成多对多数据交换，降低小消息场景下的启动开销。面向层次化集群结构，Sanders 等人提出了层次化因子分解算法\cite{sanders2002hierarchical}，在单端口节点模型下对 AlltoAll 进行分阶段组织，以更好适配跨节点与节点内通信特性。针对交换网络结构，Prisacari 等人面向 Fat-Tree 网络提出了带宽最优的 AlltoAll 数据交换算法\cite{prisacari2013bandwidth}，通过构造无争用的数据交换方案实现链路负载均衡。对于不规则多对多通信（AlltoAllV），Hofmann 等人提出了内存受限条件下的 in-place （原地交换）通信算法\cite{hofmann2010place}，在减少额外缓冲区需求的同时保持较好的通信效率。此外，Kumar 等人针对多核系统与现代互连环境分析了 AlltoAll 的扩展瓶颈，并提出面向不同消息规模的优化策略\cite{kumar2008scaling}。

近年来，面向现代互连与 GPU 集群环境，AlltoAll 的实现优化进一步从内存布局、硬件能力利用与分层组织等角度展开。Gainaru 等人利用网络硬件能力优化小消息通信开销\cite{gainaru2016using}；Khorassani 等人提出面向 GPU 集群的自适应分层算法\cite{khorassani2021adaptive}；Chen 等人给出 GPU 系统上的高效实现方案\cite{chen2022highly}；Fan 等人从算法参数配置角度探索性能优化空间\cite{fan2024configurable}；Tran 等人针对通信可扩展性与重叠执行进行优化\cite{tran2024ohio}。上述工作从算法结构、硬件特性利用与实现约束等角度为 AlltoAll 的高效实现提供了参考。

总体而言，集合通信算法设计已经从早期的固定逻辑结构发展出多种分层和多维扩展形式，在不同网络环境下取得了显著性能提升。然而，在多链路并行、复杂层级互连等新型硬件特征不断涌现的背景下，现有算法在通信轮数、链路利用率以及调度灵活性等方面仍存在改进空间，这也为进一步探索高效集合通信算法提供了持续的研究动力。



\subsection{集合通信算法自动合成}

% 相比于人为设计通信模板，算法合成希望在给定物理拓扑与资源约束条件下，自动合成集合通信的路由与调度，从而避免固定框架下的性能上限，并提升对非对称与异构系统的适配性。该方向通常将合成问题建模为约束优化或搜索问题，再利用求解器或启发式算法合成调度序列。

% 早期代表性工作 SCCL\cite{cai2021synthesizing}将集合通信合成编码为 SMT 问题，在小规模拓扑（如 DGX-1）上合成带宽最优或时延最优的新算法，但模型规模与求解复杂度限制了其扩展性。随后，TACCL\cite{shah2023taccl}将问题转化为混合整数线性规划（MILP），并结合拓扑先验与分段求解降低复杂度，以适配更大规模场景。Themis\cite{rashidi2022themis}从多维异构网络角度出发，通过贪心分配数据块实现跨维度负载均衡，提升链路利用率并缩短算子时延。

% 在自动化与通用性方面，Won 等人提出 TACOS\cite{won2024tacos}，引入时间扩展网络（TEN）表示，将合成过程转化为“数据块—链路”匹配问题，并采用启发式贪心策略在约束下逐步满足后置条件。与此同时，TECCL\cite{liu2024rethinking}借鉴流量工程思想，对路由、容量与时序进行统一建模，并以 MILP 形式求解，在复杂拓扑上具备较强表达能力。针对TECCL求解复杂度高，可扩展性弱的问题，Cao等人提出 SyCCL\cite{cao2025syccl}，通过识别拓扑中的对称性简化合成问题，并结合启发式搜索与局部优化提升求解效率，在多种典型 GPU 拓扑上均能合成高质量调度。

% % 除此之外，也有通过构建生成树或森林结构来合成集合通信算法的研究\cite{wang2020blink,zhao2024forestcoll}。

相比于人为设计通信模板，算法合成旨在在给定物理拓扑与资源约束条件下，自动合成集合通信算法，从而突破固定算法框架的性能上限，并提升对非对称与异构系统的适配能力。该方向通常将合成过程形式化为约束优化或搜索问题，再借助求解器或启发式策略合成可执行的算法。

早期代表性工作 SCCL\cite{cai2021synthesizing}将集合通信合成编码为 SMT（Satisfiability Modulo Theories） 问题，在小规模拓扑（如 DGX-1）上可合成带宽最优或时延最优算法，但其模型规模与求解复杂度限制了可扩展性。随后，TACCL\cite{shah2023taccl}将合成问题转化为混合整数线性规划（Mixed Integer Linear Programming，MILP），并引入通信草图等人为先验以约束搜索空间，同时结合分阶段求解提升在多节点拓扑上的可用性。TECCL\cite{liu2024rethinking}进一步借鉴流量工程思想，对路由、容量与时序进行统一建模，并以 MILP 形式求解，在复杂拓扑上具备较强的表达能力；针对其求解复杂度较高、扩展性受限的问题，SyCCL\cite{cao2025syccl}通过识别拓扑与通信需求的对称性分解合成任务，并结合启发式搜索与局部优化提升求解效率，从而在较大规模 GPU 拓扑上仍能合成高质量算法。

与上述以求解器为核心的方法相比，另一类工作更强调通过启发式或图方法实现可扩展的算法合成过程。Themis\cite{rashidi2022themis}从多维异构网络角度出发，通过贪心算法分配数据块实现跨维度负载均衡，以提升链路利用率并缩短算子时延。Won 等人提出 TACOS\cite{won2024tacos}，引入时间扩展网络概念，将合成过程转化为带时间维度约束的匹配问题，并采用启发式贪心策略逐步构造算法，TACOS可以高效地合成直连拓扑上的Allgather算法，并且适用于非对称异构的网络环境，但是不直接支持交换机拓扑与AlltoAll的合成。除面向通用拓扑的启发式框架外，亦有工作给出了具有理论保证的多项式时间构造方法，例如 Zhao 等人提出带宽最优算法构造方法\cite{zhao2023bandwidth}，可在任意带宽异构拓扑（包含交换机节点）上构造 AllGather/ReduceScatter 的带宽最优流水线算法，并可扩展至更多集合通信算子。
除求解器与启发式方法外，也有研究从生成树/生成森林构造角度合成集合通信算法。Wang 等人提出 Blink\cite{wang2020blink}，将集合通信算法表示为有向图上的流问题，该方法通过迭代的方式构造生成树集合并进行组合，采用整数线性规划控制树的数量。Zhao 等人提出 ForestColl\cite{zhao2024forestcoll}，同样基于生成树构造通信算法，并给出由最优二分搜索、交换机节点处理与生成树构建组成的流程，具有多项式时间复杂度，因而具备较好的可扩展性。此外，Zhao 等人提出 BFB 方法\cite{zhao2025efficient}，以广播-聚合模式进行通信，并采用广度优先策略确定数据传播顺序，在规则对称的拓扑结构上能够获得接近理论最优的通信性能。

此外，随着合成算法逐渐从离线求解走向工程化落地，一些工作开始关注合成结果的表示、编译与高效执行。
Cowan 等人提出 GC3\cite{cowan2022gc3}，提供集合通信算法的描述接口与优化编译器，可将自定义或外部合成得到的算法编译为高效可执行的实现。
在此基础上，MSCCLang\cite{cowan2023mscclang}进一步提供从算法描述到运行时执行的完整工具链，降低自定义算法的实现与集成成本，并可获得接近手写内核的性能。

总体而言，现有合成方法大致可以分为两类：一类依赖 SMT/MILP 等精确或近似求解器，算法质量较高但求解开销可能随拓扑规模急剧增长；另一类采用启发式策略或图方法合成算法，具有更好的可扩展性，但往往需要在建模精度、算子覆盖范围与系统约束表达能力之间进行权衡。尤其在多级交换机拓扑中，端口并发、转发模式与链路占用会显著影响可行性与性能，如何在保证建模准确性的同时控制合成开销，仍是该方向需要进一步解决的问题。

\subsection{研究挑战}

尽管集合通信与通算并行方向已有大量研究积累，但要在真实系统中稳定获得可观收益仍面临多方面挑战，主要体现在以下三个层面：

\begin{itemize}
    \item [（1）] \textbf{多链路并行场景下现有集合通信算法存在性能瓶颈。} 在存在多条并行链路的物理系统中，经典算法难以充分利用多种链路的并行能力，存在通信轮数偏多、链路利用率不足等问题。如何在保持工程实现简洁性与同步效率的前提下，有效聚合多条链路的传输能力，降低通信轮数、提升整体带宽利用率，并保证在不同节点规模与链路配置下的可扩展性，是集合通信算法设计面临的核心难点。
    \item [（2）] \textbf{多级交换机拓扑场景的集合通信算法自动合成难以兼顾性能与求解效率。} 在多级交换机拓扑中，人为设计的固定算法难以适配复杂的网络结构与约束，而现有自动合成方法在算法质量与求解效率之间难以取得平衡。真实集群拓扑通常包含多级交换机、端口并发限制以及不同转发模式等细节约束，如何在这些约束下于可接受时间内合成高质量的通信方案，并覆盖 AllGather、AlltoAll 等多种算子类型，是集合通信算法合成面临的主要挑战。
    \item [（3）] \textbf{张量并行训练中计算资源空闲问题突出。} 张量并行训练中频繁的同步通信往往导致显著的计算资源空闲。集合通信操作通常位于前向与反向计算的关键执行路径上，与矩阵计算存在严格的数据依赖关系；当与数据并行等其他策略混合使用时，任务调度的复杂度进一步上升。如何在满足正确性约束的前提下实现计算与通信的有效并行，并以低侵入的方式集成到主流训练框架中，是提升张量并行训练效率的关键问题。
\end{itemize}

因此，面向真实的大规模分布式训练系统，从“集合通信算法设计—集合通信算法自动合成—计算通信并行优化”三个层面探索高效、可扩展的优化方案，对提升分布式训练效率具有重要理论价值与工程意义。



\section{本文主要研究内容}

\subsection{研究思路与创新点}

结合前文背景与研究现状，针对分布式训练中通信瓶颈的研究正逐步从面向单一场景的通信算子优化，发展为面向真实物理拓扑的通信算法自动化合成与算子级计算通信协同。围绕这一发展趋势，本文以缓解分布式训练中的通信瓶颈、提高分布式训练效率为核心目标开展以下三方面研究：首先，在常见的具备双向环形链路的物理系统中，对双向环算法的通信流程进行重构，以减少通信轮数并提升有效带宽利用率；其次，面向包含交换机节点及层级互连结构的复杂系统，设计可扩展的集合通信算法合成框架，实现 AllGather 与 AlltoAll 算法的自动合成；最后，针对张量并行训练中全局同步通信导致计算资源闲置的问题，提出基于算子拆分与调度重排的计算通信并行方法，通过隐藏通信开销降低端到端训练时间。整体研究思路如\autoref{fig:framework} 所示。

本文的主要创新点可概括为以下三点：
\begin{itemize}
  \item \textbf{提出链路聚合的双半环集合通信算法。} 针对多链路并行场景下现有算法通信轮数偏多、链路利用率不足的问题，本文设计了双半环通信模式，通过重构基于传统Ring算法逻辑的双向环算法的数据传输流程，使两组反向链路在更少轮次内完成数据扩散与归约，适用于 AllGather、ReduceScatter 与 AllReduce 等算子。真实集群实验表明，该算法在多种节点规模与数据量配置下均能稳定提升通信带宽，相比经典双向环算法性能提升显著，尤其在中等数据量场景中优势更为明显。
%   \vspace{-0.5em}
  \item \textbf{提出交换机拓扑感知的集合通信算法合成框架 FTACAS。} 针对现有合成方法难以兼顾算法质量与求解效率的问题，本文提出基于时间扩展网络的事件驱动合成框架，显式建模多级交换机节点、链路特性、端口并发与转发模式等约束，采用贪心匹配策略在可控时间内合成高质量算法。FTACAS 同时支持 AllGather 与 AlltoAll 两类基础算子，在多种典型拓扑上的评估显示其在保持较高算法带宽的同时显著降低合成时间，具备良好的可扩展性。
%   \vspace{-0.5em}
  \item \textbf{提出基于算子拆分与调度重排的计算通信并行方法。} 针对张量并行训练中同步通信导致计算资源空闲的问题，本文通过将关键通信算子（AllReduce）与矩阵计算进行等价拆分并进行细粒度调度，在计算流与通信流之间建立并行执行机制。实验结果表明，在 TP/DP 混合并行训练中，该方法能够在保证训练正确性的前提下显著隐藏通信开销，有效降低端到端训练时间并提升整体吞吐。
%   \vspace{-0.5em}
\end{itemize}



\subsection{具体内容与章节安排}
